## Q29 — the hydration warning: DIAGNOSED, NOT FIXED (2026-08-26)

**What it is.** React reports one attribute mismatch on the Playbook and the dashboard:

    - className="redesign-on"

`RedesignChrome` adds that class to `<body>` from an **inline script during HTML parse**, deliberately, so the
first painted frame is already full-bleed. Without it (CAT-49) the triptych rendered inside the 720px column with
the brand bar and then snapped, and the composer could sit off-screen until hydration. React hydrates `<body>`,
finds a class the server never rendered, and warns. **The warning is real, the cause is ours, and the cause is a
fix we want to keep.**

**What I tried and REVERTED.** `suppressHydrationWarning` on `<body>` — the affordance React provides for exactly
this pattern, and what theme scripts use. It did not silence it. I did not chase why, and a suppression that
demonstrably does not suppress is worse than none: it is a rule that does not run, dressed as a solution.

**What it costs today: nothing a member can see.** React strips these warnings in production; the symptom is one
dev-console line. It is real and worth closing, but it is not a Charter blocker and it should not be closed by
guessing.

**The two candidate fixes, for whoever picks it up:**
1. Render `redesign-on` on the SERVER for redesign routes, so there is nothing to reconcile — the honest fix, and
   it needs the root layout to know the route, which it currently does not.
2. Find out why `suppressHydrationWarning` did not apply here. It may need to be on `<html>`, or the dev server
   may not have recompiled the layout during my check — which I did not rule out.
