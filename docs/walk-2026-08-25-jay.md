## FIXED DURING THE REBUILD WALK — 2026-08-26

**The ticks blinked on every tap** (Jay: *"the boxes end up checked after I select them, but are still blinking
once as I tap on the next one"*). `.wk-saving` dimmed the ENTIRE grid to opacity .85 while a toggle was in
flight — and since `router.refresh()` runs inside the same transition, "in flight" is a full server round-trip.
So each tap faded the ticks the member had already made and watched land. **A spinner over work that is already
done reads as "did that not take?" — the exact doubt the optimistic tick exists to prevent.** The dim is gone;
the class stays as a settle hook for the walk script. Verified in the browser: opacity 1 while saving.

**The walk script that should have caught it was stale in two ways**, and the second is the one worth keeping.
`w3-grid-walk.ts` anchored on the week heading "Noticing your days" — which had been renamed to "Your triggers
this week", AND which only renders when a member is running **more than one** practice week (with one, the
section title above already named it). A freshly seeded member runs exactly one, so the walk could never find its
own grid on a page where the grid was plainly rendering. It now anchors on a row the seed itself plants, so the
locator and the fixture move together. Eleven assertions green, including a new one for the blink.
