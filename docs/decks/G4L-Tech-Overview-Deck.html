Grinta for Life

A purpose-built, AI-native membership platform for midlife identity loss — engineered as a real product, not AI bolted onto a template.

Next.js 15 · React 19 · TypeScript Supabase / Postgres Anthropic Claude Vercel

Built founder + Claude Code (AI-assisted engineering) over ~6 weeks. Currently LIVE — v3.0.

The product in one slide

What we're actually building

A science-backed program that helps midlife adults reclaim a faded sense of identity — delivered through a member dashboard, an always-on AI companion, and a community, measured longitudinally.

The problem — "the Fade"

The felt distance from who you still are underneath. Deliberately narrow: we serve people with a real identity deficit, not generic self-optimizers. Scope is a locked product decision.

The program — the 4Rs

Reconnect (awareness) → Rewire (mind/habits) + Rebuild (body) run in parallel, dosed per member → Reclaim (the outcome state). Not a linear pipeline.

The measures

ID Score (identity mirror, every 60 days) · Grinta Index (daily grit/hardiness) · the Journey (place on the 4Rs). Three feedbacks, never one number.

The engineering thesis: the member experience is intentionally simple; the engine underneath is heavily engineered. Everything below is that engine.

Cowork's role (the "why")

A second AI workspace owns product/marketing/science thinking and living copy. It keeps strategy out of the build loop — the repo receives settled decisions, not open questions. Founder is the judgment layer between them.

Claude Code's role (the "how")

Persistent project memory + standing instructions (CLAUDE.md). Carries the engineering-rigor role (tests, data contracts, security posture) since the fractional senior engineer isn't hired yet. AI for velocity, human for judgment; security & data model are the review gates.

What we built — under the hood · 4

The engines

Content and rules are versioned data, not hardcoded screens. Gating and dosing are config. The core is framework-free and integration-tested.

Conversational AI kernel

One arc-turn engine runs every phase (onboarding, Reconnect, Rewire, Rebuild, Reclaim) — a 70+-stage state machine with per-turn save/resume (crash-safe), tool-use capture, and a propose→confirm→commit contract for any edit to member data.

Beat / asset-delivery engine

The "Atlas" curriculum chunked into ~70 versioned Beats; swappable protocols, A/B variant support, per-asset telemetry. Gating rules read as config so science owners change them without re-engineering.

Governance kernel

Crisis routing (regex + LLM fallback → 988 + human escalation) sits at the top of every agent turn. 9 hard prohibitions enforced in code — never diagnoses, never names an identity without confirmation, AI always disclosed.

Measurement engines

IDQ (24-item, 4-dimension, frozen scoring) · Grinta Index (14-day rolling hardiness) · administered-instrument factory (surveys → scoring → durable readings, never a bare number to the member).

State machines (v3.0)

Resume-hero (what to show a returning member), the merged progress ring, practice-week windows, quality-day logging, session artifacts — all pure functions derived from real state, unit-tested.

Data & audit

Supabase Postgres, environment-aware adapter (hosted ↔ local pglite parity), DB-level audit triggers on member data, multi-tenant columns laid in from migration 0001 (dormant).

Versioning scheme

.N = a program-phase flip · .N.x = a readiness/quality pass · a major bump (v3.0) = a whole-experience redesign.

Rollout discipline

Every phase shipped behind a feature flag, walked end-to-end on a preview, then flipped on the production env. One-line revert on any flip.

Deliberately off at launch

The Reclaim "Loop" gate (a science decision still open) and Strava (pending security review) — both built & tested, dark by a single env var.

Why a dev should care · differentiator

Safety & governance are in the code, not the copy

Crisis routing is always on

A two-layer detector (fast regex + LLM fallback) sits at the top of every agent turn — inherited by every phase for free. Distress → 988 + human escalation. Fail-safe: no API key still routes.

Hard prohibitions, enforced

Never diagnoses or pathologizes. Never names an identity label without member confirmation. AI is always disclosed. These are code paths, not guidelines.

Founder Agent: no auto-send

Any message in the founder's name is drafted only — a mandatory human review gate exists before anything sends. There is no send-without-review tool.

Privacy by construction

Minimum-necessary data; research data separated from product telemetry; DB-level audit trail on member records; multi-tenant row isolation laid in from the first migration.

The north star that governs the agent's posture: it's a place a member can be honest with themselves — non-judging, private, no social stake — in service of bridging them back to real people, never replacing them.

The private-label / B2B model foundation built

The term you're thinking of is the multi-tenant "private company instance" — a white-label deployment where a corporation funds a private, isolated instance for its own people. It's dormant by design, but the foundation is already in the schema:

  • Row-level isolation from migration 0001 — every member table carries a tenant_id
  • RLS policies written, disabled for the single public tenant
  • Agent tech spec v2.0 (multi-tenant) + governance prohibitions 10–12 already scoped
  • Locale-aware crisis routing planned per tenant

Strategy: launch a single public product, but architect for multi-tenancy from day one so a funded corporate customer can be switched on later — no re-platforming. Build the foundation now, activate under senior review when a customer pays for it.

What makes it different

This isn't a wellness app with a chatbot

Most products in this space are a content library plus a chat widget, aimed at everyone. The architecture here is a different animal — and the differences are deliberate.

AI-native, not AI-added

The companion is the product surface. The engine was designed around it — not a bot dropped onto a template.

A specific person, a specific problem

Built narrowly for midlife identity loss. Declining a no-Fade user is correct behavior, not a bug — the opposite of chase-everyone.

Governance as code, not policy

Crisis routing in the kernel, no-auto-send review gate, no identity label without consent — enforced in code paths, not a PDF.

Content & rules are data

The science owner changes gating and dosing as config. Assets are versioned Beats, never bespoke hardcoded screens.

Measurement from day one

Three feedbacks (ID Score / Grinta / Journey), longitudinal, with telemetry as a required event — not analytics bolted on later.

Non-linear program

Mind and body dosed in parallel per member; Reclaim is a temporary outcome state that loops. Not a linear course.

Safe to be honest with yourself

An agent that carries no social stake — designed to bridge members back to real people, explicitly not to replace them.

B2B-ready underneath

Multi-tenant row isolation from migration 0001 — a private corporate instance switches on without re-platforming.

The part worth being proud of

Why a six-week AI build is production-solid

Speed usually buys fragility. It didn't here — because the discipline held the whole way. That's the judgment layer, not the tooling.

Small, verifiable steps

One slice at a time, each proven working before the next. Nothing shipped on "it deployed" — it shipped on "it works," verified live after every deploy.

Revert, don't patch

On the load-bearing surfaces (the conversational capture loop), a regression gets reverted to last-known-good, not buried under another guard. The core stays clean.

Flag-gated flips, one-line reverts

Every phase built behind a feature flag, walked end-to-end on a preview, then flipped on prod — reversible in a single env change. No irreversible big-bangs.

Tests as the safety net

~770 tests + a replay-fixture harness for the AI: real conversation bugs become CI regressions, not live surprises. The core is framework-free and tested against real Postgres parity.

The result: a governed, tested, versioned platform that holds vulnerable people's stories with care — built fast and built to last. AI carried the throughput; human judgment set the bar, consistently. That combination is the actual product here.
